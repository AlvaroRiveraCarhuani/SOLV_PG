# Feature: Catalog Guided Ecosystem UX & Zero-Command Component Authoring
Branch: main | Delivery strategy: ask-on-risk | Test runner: go test ./... & npm run test:ci

## Specs
- **S1**: Separar C y C++ en el catálogo institucional en dos perfiles independientes de Columna 1: `C (GCC 13)` (`c-gcc13`, `gcc -O2 solution.c -o solution && ./solution`) y `C++ (G++ 13)` (`cpp-gcc13`, `g++ -O2 solution.cpp -o solution && ./solution`), compartiendo la misma imagen base `gcc:13.2-bookworm` y compatibilidad `["c", "cpp"]`, más semillas curadas de Columna 2 para C/C++ (`GDB + Valgrind`, `CMake + Ninja`, `GoogleTest`), Go, Rust y Java para que escenarios como `LAB-1.2 (Medio): Estructuras de Datos en C/C++ (gcc + gdb + valgrind + cmake)` se armen con clics visuales sin abrir el modal de registro manual.
- **S2**: Rediseñar el modal de registro de Lenguaje Principal (`component-form-modal`) para que el administrador elija de un catálogo de **Perfiles de Ecosistema Oficiales** (C, C++, Python, Java, Node.js, Go, Rust, PHP, .NET/C#) que auto-resuelven la imagen oficial de Docker (sin `:latest`), el comando del Juez Virtual (`judge_entrypoint`), los binarios base (`tools_provided`), el icono y el perfil de memoria sin obligar al administrador a escribir tags de Docker ni comandos de compilación.
- **S3**: Bloquear gestores de paquetes incompatibles a presente y futuro al registrar o editar Complementos (Columna 2) o Runtimes: el complemento hereda el gestor nativo del lenguaje padre seleccionado (`pip`/`uv` para Python, `npm` para Node/Web, `apt` para C/C++, `cargo` para Rust, `go` para Go, `composer` para PHP) y solo permite alternar entre el gestor nativo de ese ecosistema y utilidades del sistema Linux (`apt`), impidiendo mezclar gestores ajenos (como `npm` en C++).
- **S4**: Unificar la entrada de paquetes/herramientas y su verificación al iniciar: eliminar el selector manual de `"Perfil de Consumo en Memoria"` de la vista normal del administrador (el sistema infiere la huella de memoria automáticamente por arquitectura de runtime y tipo de complemento) y sincronizar automáticamente los paquetes/herramientas con la verificación de inicio (`tools_provided` para paquetes `apt` y soporte en `RunSmokeTest` para validar tanto binarios con `command -v` como paquetes Debian/Alpine instalados con `dpkg -s` / `apk info -e`), manteniendo un interruptor opcional colapsado de `"Modo experto (contenedor)"` para personal de infraestructura.
- **S5**: Actualizar la documentación técnica (`ADR-046`) y la guía del piloto (`docs/PILOT/01-ADMIN/`) reflejando la separación C vs C++, los kits pre-sembrados y el flujo guiado sin comandos.
- **S6**: Reemplazar el combobox estático por una **Grilla de Tarjetas de Catálogo Contextual (1 clic)** para Lenguajes Principales, Plataformas Web (`Angular`, `React + Vite`, `Vue 3 + Vite`, `Vite`) y Kits de Complementos filtrados por ecosistema (`GDB + Valgrind`, `CMake + Ninja`, `GoogleTest`, `FastAPI`, `Django`, etc.), filtrar estrictamente la galería de iconos por columna/ecosistema (excluyendo motores de base de datos de Columna 3 y tecnologías ajenas), hacer que el clic en una tarjeta de la galería autocomplete el perfil técnico completo y restaurar idempotentemente los 25 componentes del catálogo institucional en `00024` y `solv_db`.
- **S7**: Implementar **Parametrización Abierta de Versiones** (`imageTemplate` + `suggestedVersions` + input libre de versión en `ComponentFormModalComponent`), **Gestores de Paquetes de Primera Clase en el Servidor** (`pip`, `uv`, `npm`, `pnpm`, `yarn`, `bun`, `apt`, `cargo`, `go`, `composer`, `dotnet` en `domain.SynthesizeAssistedBuildLayer` y `CHECK` de PostgreSQL) y resolución dinámica de imagen base web desde el catálogo activo sin hardcodes.
